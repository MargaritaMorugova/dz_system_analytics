# dz_system_analytics

## Функциональные требования к системе заказа наличных в отделении банка

### FR-01. Управление клиентами
- Система должна хранить информацию о клиентах
- Система должна управлять лимитами снятия (дневные, недельные, месячные)
- Система должна рассчитывать комиссии по заказам
### FR-02. Справочники
- Система должна поддерживать справочник валют
- Система должна поддерживать справочник номиналов купюр
- Система должна поддерживать справочник статусов заказов
### FR-03. Заказы наличных
- Клиент может создать заказ на снятие наличных
- Заказ содержит общую сумму, валюту и состав по номиналам
- Заказ привязан к конкретному отделению банка
- Заказ связан со счетом клиента для списания
### FR-04. Состав заказа
- Заказ может содержать несколько номиналов одной валюты
- Для каждого номинала указывается количество купюр
- Система должна проверять доступность номиналов в отделении
### FR-05. Статусы заказа
- Система должна отслеживать жизненный цикл заказа
- Поддерживаемые статусы: новый, подтвержден, в процессе, готов, выдан, отменен
- Смена статуса фиксируется с указанием исполнителя
### FR-06. Остатки наличных
- Система должна вести ежедневный учет остатков по отделению
- Остатки учитываются по валютам и номиналам
- При подтверждении заказа остатки резервируются
### FR-07. Инкассация
- Система должна фиксировать поступления наличных от инкассаторов
- Система должна фиксировать изъятия наличных инкассаторами
- Движения инкассации влияют на остатки
### FR-08. Выдача наличных
- Система должна фиксировать факт выдачи заказа клиенту
- Выдача сопровождается списанием с резерва остатков
- Фиксируется исполнитель выдачи и подпись клиента
### FR-09. Управление отделениями
- Система должна хранить справочник отделений банка
- Каждое отделение имеет свои остатки и заказы
- Сотрудники привязаны к конкретным отделениям
### FR-10. Управление пользователями
- Система должна поддерживать роли операционистов и администраторов
- Все действия пользователей логируются
- Пользователи привязаны к отделениям
### FR-11. Уведомления
- Система должна отправлять уведомления о статусе заказа
- Поддерживаются различные каналы уведомлений
- Фиксируется статус доставки уведомлений
### FR-12. Аудит и логирование
- Система должна вести полный аудит изменений заказов
- Фиксируется кто, когда и что изменил
- Логируются критические операции (выдача, инкассация)
### FR-13. Проверки и ограничения
- При создании заказа проверяются лимиты клиента
- Проверяется наличие достаточных остатков на дату выдачи
- Автоматический отказ при превышении лимитов/остатков
### FR-14. Списание со счета
- Заказ связан с конкретным счетом клиента
- При выдаче происходит списание с указанного счета
- Фиксируется комиссия за заказ

## Описание таблиц и их атрибутов

| Таблица            | Описание                                      |
| ------------------ | --------------------------------------------- |
| **Currency**       | Справочник валют (RUB, USD, EUR)              |
| **OrderStatus**    | Статусы заказов (Новый, Выдан, Отменен)       |
| **Nominals**       | Номиналы купюр по валютам (1000 RUB, 100 USD) |
| **Client**         | Клиенты банка с лимитами и комиссиями         |
| **Offices**        | Отделения банка                               |
| **Account**        | Банковские счета клиентов                     |
| **Orders**         | Заказы наличных                               |
| **OrderItem**      | Детали заказа по номиналам                    |
| **Balance_office** | Ежедневные остатки наличных в отделении       |
| **CashTransit**    | Инкассация (поступления/изъятия)              |
| **CashIssue**      | Факт выдачи наличных клиенту (3НФ)            |

## Изменения аналог ПВЗ:
- Ввести доп атрибуты для самих товаров по типу (артикул, наименование товара, цена за шт/за вес)
- Мб ввести доп атрибуты для самих точек-отделений по типу (наименование; мб отдельную сущность создать с коммисиями под каждую точку; мб какая-то информация по логистике между объектами - сейчас для банка у нас логика такая, что деньги только привозятся/забираются из вне инкассаторами, и никак не перемещаются между отделениями)
- Ну остатки соответсвенно по товарам, а не купюрам
